## The seven invariants

Violating any of these is a defect even if tests pass.

1. **Money is `int64` paisa.** Never float. Never a decimal string in JSON.
   ৳12.40 is `1240`. Format only at the rendering edge.
2. **Append-only.** `ledger_entries`, `meal_exceptions`, `period_statements`
   are never UPDATEd or DELETEd. Corrections INSERT a row with `void_of` set.
   Postgres RULES enforce this. If your code needs an UPDATE, the design is wrong.
3. **Derived is never stored.** Daily meal counts are materialized from
   `patterns ⊕ exceptions ⊕ day_flags` on read. The only snapshot is
   `period_statements`, written once at close.
4. **`tenant_id` on every row, tenant scope on every query.** RLS is a
   backstop, not the primary defence.
5. **`Asia/Dhaka`, server-side.** Never trust the device clock for a date
   boundary or cutoff.
6. **Entitlements go through `Has(ctx, tenant, feature, on_date)`.** Returns
   true in v1.0. Never write inline billing logic.
7. **If it is not in `docs/product/BRD.md` §7.1, it is not in v1.0.**
   Propose it as a P2 item instead of building it.

## Commands

```bash
make verify   # THE GATE — lint, test, property, golden, contract, invariants
make dev      # boot postgres + api
make proto    # regenerate Go server + TS client + Dart models
make sqlc     # regenerate db layer after editing queries/*.sql
make tokens   # regenerate Dart theme + Tailwind + CSS from tokens.json
make smoke    # end-to-end scenario
```

**A task is done when `make verify` is green AND a human has read the diff.**

## Working protocol

1. Find your task in `docs/product/EPICS.md`. Note its Done-when and Owner.
2. **If Owner is ★, STOP.** That task is hand-written by the founder.
   Offer to scaffold tests only.
3. Read the nested `AGENTS.md` in the directory you are about to change.
4. State a plan in 3–6 bullets. Wait for approval if it touches `proto/`,
   the engine, or a migration against an existing table.
5. Write the test first for anything touching money.
6. Implement the **smallest** change that satisfies Done-when.
7. Run `make verify`.
8. Report:

```
Changed:            files and why
NOT done:           anything deliberately skipped
Needs human review: judgement calls made
Next task:          id only
```

## Stop and ask when

- The task implies a feature outside BRD §7.1.
- The prototype shows something an accepted ADR contradicts. The ADR wins on
  architecture and auth; the prototype wins on layout and interaction.
- A proto change would fail `buf breaking`.
- An append-only table needs altering.
- The task's Owner is ★.
